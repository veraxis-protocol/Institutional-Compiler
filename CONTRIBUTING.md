# Contributing

Every material pull request must state:

1. Customer problem and TDD requirement/invariant served.
2. Modules and interface versions changed.
3. Build/reuse decision and dependency effect.
4. Tests, fixtures, benchmark partition, and evidence-class effect.
5. Security and privacy impact.
6. Failure, rollback, and blast-radius behavior.
7. Claims and limitations impact.
8. Hosted/open semantic-parity impact.
9. ZTL/VEIP provisional-boundary impact.

Candidate extractions, benchmark annotations, and review decisions must never be mixed in one unlabeled artifact.
