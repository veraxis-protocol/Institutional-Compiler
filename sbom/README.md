# Software Bill of Materials

Generated by [`scripts/generate_sbom.sh`](../scripts/generate_sbom.sh) from the installed
Python environment. **Do not edit these files by hand.**

| File | Contents |
|---|---|
| `oic-python.cdx.json` | CycloneDX 1.6 SBOM of every installed Python component |
| `LICENSES.json` | Per-package license, author, and project URL |
| `DEPENDENCY_INVENTORY.md` | Human-readable package/version/license table and direct requirements |

## What ties these to the lockfile

CI installs with `pip install --require-hashes -r requirements/dev.txt`, so every artifact
in the environment had its hash verified before installation. The SBOM is then generated
*from that environment*, which is what prevents the SBOM and the lockfile from drifting
apart. Regenerate after any change to `requirements/*.in`.

`cyclonedx-py` runs with `--output-reproducible`, so it emits no timestamp and no random
serial number: re-running against an unchanged environment produces a byte-identical
`oic-python.cdx.json`.

## Snapshot status

These files are a point-in-time snapshot committed as review evidence for
`CLAUDE-FABLE5-WO-001`. CI regenerates them on every run and uploads them as build
artifacts; treat the CI artifact as authoritative for any given commit.

`DEPENDENCY_INVENTORY.md` records the generating machine's platform, so that one line
differs between a local run and a CI run. Everything else is environment-independent.
