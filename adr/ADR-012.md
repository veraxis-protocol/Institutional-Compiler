# ADR-012: Artifact Lifecycle and Amendment

**Status:** Accepted
**Supersedes:** the working assumption in `CLAUDE-FABLE5-WO-001` that every path listed in
`BOOTSTRAP_MANIFEST.json` is permanently frozen in the working tree.

## Context

`BOOTSTRAP_MANIFEST.json` records a path, SHA-256, and byte count for each of the 50
artifacts checked in at the bootstrap commit. The first implementation of
`oic verify-manifest` compared those records against the **current working tree**, which
made every listed path immutable for the life of the repository.

That reading is wrong, and it produced a false alarm the first time a listed file
legitimately changed: PR #2 rewrote `adapters/ztl/README.md` from 75 to 2271 bytes, and
CI reported a bootstrap-integrity violation. The change was legitimate; the control's
scope was not. Under the working-tree reading, the only way to accept any later change to
a listed path is to rewrite the manifest — which would destroy the historical evidence the
manifest exists to preserve.

## Decision

### 1. The bootstrap manifest is immutable historical evidence

`BOOTSTRAP_MANIFEST.json` is evidence about one commit:

```
8b06b8a7f1a319a0b5ceeea6857eefa30b9eb081
```

It is not a policy about the current working tree.

### 2. It must never be rewritten to make a later working tree match

Amending the manifest so that a changed file "passes" destroys the only record of what the
bootstrap contained. A manifest that is edited whenever it disagrees with reality verifies
nothing. If the manifest and the bootstrap commit ever disagree, the manifest is wrong and
the fix is to correct the manifest to match history — never the reverse.

### 3. Bootstrap verification reads history, not the working tree

To verify the bootstrap:

- load `BOOTSTRAP_MANIFEST.json` **from the pinned bootstrap commit**;
- load each listed file **from that same commit**, through the local Git object database;
- verify the exact blob bytes and the recorded byte count;
- perform no checkout, no mutation, and no network fetch.

The working tree is not consulted. A file modified in a later commit cannot invalidate the
historical baseline, because the historical baseline is not about that file's present
contents.

### 4. The bootstrap manifest is not a permanent freeze on the paths it listed

Being listed in the manifest is a statement that a path existed with certain bytes at the
bootstrap commit. It is not a statement that the path may never change again. What governs
a path's mutability is its class, below.

### 5. Artifact classes

**CLASS A — IMMUTABLE HISTORICAL BASELINE**

- the bootstrap commit `8b06b8a7f1a319a0b5ceeea6857eefa30b9eb081`;
- `BOOTSTRAP_MANIFEST.json` as it exists at that commit;
- `docs/tdd/TDD-OIC-001-v1.1.pdf` and its governing digest
  `2a4d802130d577e4fb8fee731174ae0f2172ef2d617e3b99f068545d2b9fbf77`.

Class A never changes. The TDD PDF is additionally verified against the **current** working
tree, because it is immutable as a live artifact and not merely as history.

**CLASS B — GOVERNED MUTABLE CONTRACTS**

- `docs/requirements/REQUIREMENTS.md`;
- `docs/requirements/INVARIANTS.md`;
- `schemas/draft/*.schema.json`;
- `STATUS.md`;
- `DEPENDENCIES.md`;
- `CLAIMS.md`;
- `LIMITATIONS.md`;
- `GOVERNANCE.md`;
- ownership and interface contracts (`OWNERS.md`, adapter interface definitions).

These may change only through an explicit pull request carrying: identified owner review, a
stated reason, a compatibility-impact assessment, tests, and an ADR where the change is
material.

**CLASS C — OPERATIONAL MUTABLE ARTIFACTS**

- adapter READMEs;
- implementation code;
- tests;
- operator documentation;
- CI configuration;
- dependency and infrastructure files.

These change through ordinary pull-request review.

### 6. `adapters/ztl/README.md` is Class C

Its change in PR #2 is not a corruption of the historical bootstrap. It is a legitimate
later repository change. The historical baseline still verifies, because it is evaluated at
the bootstrap commit where that file's bytes are unchanged and always will be.

### 7. A governed-current-state registry is out of scope here

Class B artifacts are currently protected by review discipline, not by a machine-checked
digest registry. A registry recording current expected digests for Class B may be
introduced under a separate work order. **It is deliberately not invented or implemented in
this pull request.**

### 8. `STATUS.md` remains controlling

`STATUS.md` is the controlling record for release status and the semantic implementation
gate. No verification tool, CI job, dossier, or commit message changes that status. A tool
may report the gate; only an authorized change to `STATUS.md` moves it.

## Consequences

- `oic verify-bootstrap` is added, reading the manifest and every listed blob from the
  pinned commit through the local Git object database.
- `oic verify-manifest --all` uses historical baseline verification for its bootstrap
  component. The `SHA256SUMS` and source-manifest components keep their documented
  current-tree behaviour, because those verify present artifacts rather than history.
- CI runs `oic verify-bootstrap`, and separately re-checks the literal TDD digest against
  the working tree.
- Changing a Class C file no longer fails CI, and no longer creates pressure to rewrite the
  manifest.
- Class B protection remains procedural for now. That is a known, accepted gap recorded
  here rather than papered over.
