# ADR-011: Python Dependency Workflow and Lockfile

**Status:** Accepted
**Scope:** Repository build contract only. No semantic or architectural boundary is affected.

## Decision

The reference implementation uses **pip + pip-tools** with `pyproject.toml` (PEP 621 metadata,
setuptools build backend) and fully pinned, hash-locked requirement files:

- `requirements/runtime.in` -> `requirements/runtime.txt`
- `requirements/dev.in` -> `requirements/dev.txt` (superset of runtime)

Both lockfiles are generated with `pip-compile --generate-hashes` and are checked in.
Installation in CI uses `pip install --require-hashes -r requirements/dev.txt`.

## Reason

- `pip` and `venv` ship with CPython 3.12, so a clean clone needs no bootstrap installer.
- `--generate-hashes` gives artifact-level reproducibility that matches the integrity posture
  this repository already applies to its own bootstrap artifacts (`BOOTSTRAP_MANIFEST.json`,
  `docs/tdd/SHA256SUMS`).
- `pyproject.toml` stays the single source of dependency ranges; the lockfiles are derived.
- No new project manager is introduced, so no contributor is required to install Poetry, uv,
  PDM, or Hatch to build or test the project.

## Rejected alternatives

- **Poetry / PDM / Hatch** — each adds a required non-stdlib project manager and its own
  resolver semantics for no benefit this work order needs.
- **uv** — fast and lock-capable, but at time of writing it adds an external toolchain
  dependency whose availability the repository would then have to pin and verify. It remains a
  reasonable future migration; changing it requires a superseding ADR.
- **Unpinned `pip install -e .[dev]`** — cannot satisfy the reproducibility requirement.

## Consequences

- Dependency changes are a two-step edit: change the `.in` file, regenerate the `.txt` lock.
- The lockfile is platform-resolved by the environment that runs `pip-compile`. Python is pinned
  to `>=3.12,<3.13` for this work order so resolution stays stable.
- SBOM generation (`cyclonedx-py`) reads the same locked environment, so the SBOM and the lock
  cannot drift from one another.
